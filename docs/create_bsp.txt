These instructions are only for creating a BSP adn APP from scratch.

1.    From the niosv-shell.exe (c:\altera\25.1std\niosv\bin) run niosv-bsp-editor.exe
2.    File->New BSP, opening and editing an existing BSP doesn't seem to work!
3.    Select the de0_fpga.sopcinfo file at de0_top\PR_RF\, this file
      was generated by the platform designer after Generate HDL
4.    Uncheck "Use default locations"
5.    Create folder d:\de0_opto_fpga\nios\de0_bsp and Select for BSP target directory
6.    Select altera_ro_zipfs under Software Packages
7.    Select 0x02000000 for ro_zipfs_base address, offset is 0x00200000
8.    Leave all drivers selected
9.    Change the Linker Script :
            Add sdram_fifo,   0x00800000 - 0x01FFFFFF sdram    25165824    8388608
            Add sdram,        0x00000000 - 0x007FFFFF sdram    8388608     0

15.   Under BSP Editor Main tab, sys_clk_timer = cpu, timestamp_timer = cpu (usually DEFAULT settings)

16.   Generate and Save


###


1.    If a new firmware project is need then from the niosv-shell.exe
            [niosv-shell] d:\niosv-app -a=de0_fw -b=de0_bsp -s=de0_fw/main.c
2.    Run Ashling RiscFree IDE and import preference file utils/eclipse.epf,
      File->General->Preferences (then Restart)
2.    File->Import Nios V CMake project de0_bsp, set text file encoding to other->UTF-8
3.    File->Import Nios V CMake project de0_fw
4.    Import C/C++ Project Settings->include_search_path_25.1std.xml for de0_fw project
5.    Project->Clean uncheck clean all projects, select de0_bsp and build only selected projects
6.    First time launch of Ashling RiscFree IDE doesn't populate the Console output correctly so relaunch

*** fix warning misleading indentation for BSP only***
add -Wno-misleading-indentation to hal.make cflags_warnings

7.    Editing of the BSP does not appear to work, if Qsys changes and the BSP must be updated
      then the BSP must be regenerated from scratch.
